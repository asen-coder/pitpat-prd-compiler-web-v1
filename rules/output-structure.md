# 输出目录与文件命名规范（唯一事实源）

> 本文件是 PRD Compiler 输出结构与命名的**唯一权威来源**。SKILL.md / phase1.md / phase2.md 均引用本文件。
> 本规范**覆盖**任何历史命名约定（含旧的 `prd-[english-kebab-case-name]-[version].md` 格式）。

## 1. 版本目录

每次编译在输出根目录下，按 APP 版本号建立一个版本文件夹：

```
APP_v<MAJOR>.<MINOR>.<PATCH>
```

- **版本号来源**：输入素材中的版本号（如墨刀标题「4.19」、PRD 标注版本等）。
- **补齐规则**：若版本只给出两段 `X.Y`，补齐为 `X.Y.0`。例：`4.19` → `APP_v4.19.0`。
- 若素材未给出版本号，向用户询问，不自行编造。
- 版本文件夹下固定包含两个子目录：`document/` 与 `prd_md/`。

## 2. `prd_md/` — Phase 1 原始需求文档

- 存放 **Phase 1** 生成的原始需求文档（描述 What，即 prd.md 内容）。
- **每个需求一个独立 `.md` 文件**。
- 内容、结构、编号规范遵循 `templates/prd-phase1-template.md` 与 `phases/phase1.md`。

## 3. `document/` — Phase 2 技术文档

- 存放 **Phase 2** 生成的技术实现文档（描述 How：结合 pitpat-h5 `CLAUDE.md` 前端工程规范 + 源码扫描结果映射到 pitpat-h5 架构）。
- **每个需求一个独立 `.md` 文件**，与 `document/` 中的同名需求一一对应。
- 生成方式：先按 `templates/prd-phase2-template.md` 产出 Markdown


## 4. 文件命名（中文，见名知义）

- 文件名使用**简体中文**，准确概括该需求，让人一眼明白是什么需求。
- **禁止**英文 kebab-case；**禁止**在文件名中写版本号（版本已体现在目录层级）。
- `prd_md/` 与对应 `document/` 文件**同名**（仅扩展名不同）。
- 命名以「核心需求名（可选括号补充关键子项）」为准，简洁优先。
- 示例：
  - `prd_md/积分签到（每日签到与补签卡）.md`
  - `document/积分签到（每日签到与补签卡）方案设计.md`

## 5. 文件顶部声明

每个生成文件顶部保留文件声明，路径使用本规范的新结构（相对版本目录）：

```text
📁 **File: APP_v<版本>/prd_md/<中文需求名>.md**
📁 **File: APP_v<版本>/document/<中文需求名>方案设计.md**
```

## 6. 完整结构示例

```

    document/

    prd_md/
      积分签到（每日签到与补签卡）.md
      商城入口迁移.md

```
